CUDA box IoU triangle buffer capacity
=====================================

Pull request: https://github.com/facebookresearch/pytorch3d/pull/2059
Issues:       https://github.com/facebookresearch/pytorch3d/issues/1777
              https://github.com/facebookresearch/pytorch3d/issues/1805
Revisions:    baseline     88e182f (main)
              first commit 203555b Fix CUDA box IoU triangle buffer capacity
              fixed        0d0f69e Drop IoU CUDA clip copy-back and coplanar keep buffer
Environment:  Linux, Python 3.12.13, PyTorch 2.11.0+cu130, CUDA 13.0,
              NVIDIA B200 (148 SMs, sm_100).

Measured defect
---------------
The baseline CUDA kernel stores clipped triangles in fixed MAX_TRIS = 100
per-thread arrays. On the #1805 boxes the clipped surface has 31 triangles on
one side and 109 on the other (clip-counts.csv; the native CPU and CUDA helper
traces agree). The baseline CUDA result disagrees with CPU and depends on the
argument order; the fixed kernel agrees with CPU in both orders
(issue1805-results.csv):

  build     order   CUDA IoU   CPU IoU
  baseline  (a, b)  0.151524   0.166918
  baseline  (b, a)  0.437978   0.166918
  fixed     (a, b)  0.166918   0.166918
  fixed     (b, a)  0.166918   0.166918

Files
-----
- iou-capacity-comparison.png/.svg: figure generated by make_evidence.py.
- issue1805-results.csv, issue1805-{baseline,fixed}.json: #1805 boxes through
  the native extension (_C.iou_box3d) on CPU and CUDA; captured by
  compare_issue.py with fixture1805.json.
- clip-counts.csv, native-{cpu,gpu}-counts.json: triangle count after each of
  the six clipping planes, from cpu_counts.cpp / gpu_counts.cu (which call the
  production clipping helpers; gpu_counts.cu also records where a smaller
  capacity would first overflow).
- benchmark-results.csv, benchmark-{baseline,first-commit,fixed}.json: latency
  and memory per case, one fresh process per case, 5 warmups, median of 31
  CUDA-event samples (benchmark_native.py). Baseline is omitted on the #1805
  inputs because it writes out of bounds there.
- ptxas-{baseline,first-commit,fixed}.txt: kernel registers and stack size.
- fixed-module-suite.log: tests/test_iou_box3d.py on the fixed code
  (18 passed).
- fixed-sanitizer-regressions.log: the 12 new regression tests
  (run_regressions.py) under compute-sanitizer memcheck (0 errors).
- first-commit-*.log: the same checks on 203555b.
- sanitizer-small-capacity.log: a diagnostic build of the production helpers
  with capacity 100 stops at the new CUDA_KERNEL_ASSERT before writing out of
  bounds (expected non-zero exit).
- issue-baseline-sanitizer.log: the baseline kernel on the #1805 input runs
  clean under memcheck while returning the wrong IoU, so memcheck alone does
  not detect the capacity loss.
- rotated-stress.json: 12x15 independently rotated, high-overlap boxes; CPU
  vs CUDA and argument-order symmetry errors (validate_rotated.py).
- bitwise.py: compares two builds' outputs on 202x152 rotated pairs plus the
  #1805 boxes; 203555b and 0d0f69e are bitwise identical.
- build_variant.py: local helper that recompiles only iou_box3d.cu and links
  it with cached objects; it needs a local native/build-manifest.json and is
  included for transparency. A normal "python setup.py build_ext --inplace"
  build is equivalent.

Reproduce
---------
Build the native extension at the baseline and fixed revisions. With
BASELINE_SO / FIXED_SO the built _C*.so files and this directory as cwd:

  python compare_issue.py "$BASELINE_SO" > issue1805-baseline.json
  python compare_issue.py "$FIXED_SO"    > issue1805-fixed.json
  python benchmark_native.py --extension "$FIXED_SO" --device 0 \
      --fixture fixture1805.json --include-issue --output benchmark-fixed.json
  python make_evidence.py

From the fixed checkout (with its extension built in place):

  python -m pytest tests/test_iou_box3d.py
  compute-sanitizer --tool memcheck --error-exitcode 86 python <this dir>/run_regressions.py

Limits
------
- One GPU model and one software stack. The full repository test suite was not
  rerun for this change.
- Large batches are slower than the baseline (up to 4.4x at 100x100) because
  the 253 MiB workspace cap limits the kernel to 2400 concurrent workers.
- Local paths in logs are replaced with <checkout>, <python-env>, <path>.
